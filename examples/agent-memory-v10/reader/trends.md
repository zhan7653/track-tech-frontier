# 近期变化：Agent Memory 正从“存下来再搜索”走向受管理的状态

**主体研究快照：2026-08-10；Codex 工程增量：2026-08-23。** 本文只讨论仍在当前技术脉络中的做法、过去 12 个月出现的实质变化，以及过去 90 天尚待验证的信号；它不是一章奠基史，也不把刚发布的论文或仓库自动视作重要突破。完整的旧版研究底稿可从 [v09 的时间脉络](../../agent-memory-v09/bundle/reports/04-history-and-causality.md) 和 [GitHub 雷达](../../agent-memory-v09/bundle/reports/06-github-trend-radar.md) 追溯。Codex 增量只更新现役 Coding Agent Memory 这一处工程证据。

## 一眼看懂

当前主流不再把 Memory 简化为“把历史切块、嵌入，然后 top-k 搜索”。更常见的系统把它看作会演化的外部状态：先判断输入是否值得写入，再保存事实、事件、偏好、技能或环境状态；随后按任务、时间、权限和预算构造上下文；最后还要处理更正、冲突、撤销、遗忘和行动后的反馈。

过去 12 个月最实质的变化集中在五处：记忆对象开始有类型和版本；写入与更新成为显式操作；评测从“能否答出旧事”扩展到写、改、忘和行动；安全开始覆盖从低信任写入到未来工具行动的整条链；而技能、项目和世界状态不再被笼统叫作“长期对话历史”。这些是多篇工作在不同机制上指向同一问题后的综合判断，不意味着已经存在统一架构或统一效果排名。

| 变化 | 它在解决什么 | 当前判断 |
|---|---|---|
| 类型化、时间化的状态 | 区分“谁的、何时有效、来自哪里”的事实 | 方向明确；表示优劣仍依任务而变 |
| 生命周期与控制面 | 决定何时写、合并、更正、忘却和恢复 | 研究议题已确立；自动控制的效果和安全性尚未独立确认 |
| 面向行动的评测 | 不再只测历史问答，也测更新、工具调用与遗忘 | 评测任务正在分化，分数不能合并成总榜 |
| 持久记忆安全 | 防止低信任内容变成未来的检索上下文或行动依据 | 威胁链已被多次展示；端到端防御证据仍薄 |
| 记忆对象分工 | 将程序、共享状态、个性化与世界状态分开处理 | 分类转向可信；跨类别性能比较尚不成立 |

## 当前主流：外部状态、选择性读取和生命周期并行存在

今天最稳定的共同点是职责分开，而不是底层存储收敛。一个系统往往有持久存储、读时检索与上下文编译、以及写入或更新的管理层；向量、关键词、图、文件或关系数据库都可能出现在其中。MemoryOS 将存储、更新、检索和生成显式拆开；较新的 MemTxn 则把写入验证、版本选择和恢复日志放在回答模型之外。[MemoryOS](https://arxiv.org/abs/2506.06326) [MemTxn](https://arxiv.org/abs/2607.27834)

这并不证明复杂系统必然胜过简单历史检索。一项对 LightMem 的独立复现发现，固定构造出的 memory store 的表现会被 retriever 与 token 预算显著改变；在其匹配条件下，保留原始轮次的朴素 RAG 往往更强，而构造后的记忆主要在很紧的回答 token 预算下显示优势。[Reproducing LightMem](https://arxiv.org/abs/2607.29104) 因此，“引入更多记忆机制”不是一个可脱离任务、预算和读取器的结论。

## 过去 12 个月：五条机制脉络

### 1. 状态表示开始保留时间、身份和来处

扁平语义检索擅长找相近文本，却不天然回答“这个事实属于谁”“当时是否为真”“后来是否被修正”。近一年的工作因而把原子事实、事件、档案、实体和版本区分开：AtomMem 由原子事实组织出事件、时间档案和关联图；一项双时间图存储同时记录事实的有效时间与系统得知它的时间。[AtomMem](https://arxiv.org/abs/2606.19847) [Graph-Native Bitemporal Memory Store](https://arxiv.org/abs/2607.26520)

这一脉络可以确认的是：时间、范围、来源和冲突已成为可实现的表示问题，而不再只是提示词里的文字说明。不能确认的是某种结构总会带来更好回答。双时间工作自己的小样本结果就显示，知识更新回忆提高的同时，时间推理可能下降；过滤也可能耗尽候选集合。[Graph-Native Bitemporal Memory Store](https://arxiv.org/abs/2607.26520)

### 2. “如何管理记忆”被单独当作问题

过去常把总结、合并和删除视为存储前后的启发式。最近的研究更明确地把它们列为运行时操作：MemCon 在检索、向计划注入、再次检索、巩固、遗忘和不操作之间做在线选择；ForgetEval 把“还能回忆”和“已被替代、释放或彻底清除”分开测量；MemTxn 则关注提交前验证、时间版本和故障恢复。[MemCon](https://arxiv.org/abs/2607.13591) [ForgetEval](https://arxiv.org/abs/2606.15903) [MemTxn](https://arxiv.org/abs/2607.27834)

这是一条**已确认的研究转向**：更新、巩固和遗忘已被明确建模和评测。它仍是**有条件的工程结论**：巩固能在紧预算下提高单位 token 的覆盖，却可能抹掉之后问题需要的细节；相关研究没有给出 Merge、Abstract、Rewrite 等操作的普遍排序，而 MemCon 的收益也缺少本底稿内的独立长期复现。[Budgeted Memory Consolidation](https://arxiv.org/abs/2607.17545) [MemCon](https://arxiv.org/abs/2607.13591)

### 3. 评测从回忆问答扩展为状态改变和行动

LongMemEval、LoCoMo 一类任务仍是理解长对话记忆的重要基线，但它们主要问“能否从固定历史中答对”。过去一年出现的基准把问题拆开：MemoryAgentBench 覆盖检索、测试时学习、长程理解和选择性遗忘；Mem2ActBench 与 MemoryArena 把记忆放回工具或环境循环；MemSecBench 则以写入、执行、遗忘的连续过程考察安全。[MemoryAgentBench](https://arxiv.org/abs/2507.05257) [Mem2ActBench](https://arxiv.org/abs/2601.19935) [MemSecBench](https://arxiv.org/abs/2607.27080)

这可以稳妥地称为**评测协议的确认性分化**，而不是一套更好的总排行榜。静态问答、增量更新、工具成功率、多方共享、多模态感知和安全生命周期的输入、允许访问的状态、Agent 循环与评分器不同；跨协议直接比较一个 headline score 会丢失关键信息。

### 4. 安全边界延伸到“写入—保存—取回—行动—修复”

持久状态使一次低信任输入能够跨会话重现。近期研究既展示攻击链，也开始拆开防护责任：MAFIA 考察在大量看似正常的候选内容中绕过主动审计；Salami Attack 将单独无害的片段组合为有害记忆；MutMem 试图让状态变更具备可验证的来源链；DP-MemView 关注重复响应造成的隐私泄露；STALE 则表明 store 更新并不保证 Agent 的行为已经摆脱旧状态。[MAFIA](https://arxiv.org/abs/2608.03844) [Salami Attack](https://arxiv.org/abs/2608.01637) [MutMem](https://arxiv.org/abs/2608.02843) [DP-MemView](https://arxiv.org/abs/2608.03130) [STALE](https://arxiv.org/abs/2605.06527)

因此，**威胁面已经得到确认**：memory 的安全不能只看输入过滤，还涉及写入资格、版本与来源、读取范围、工具行动时的再授权，以及删除或修复是否传播到摘要、索引和缓存。相反，**防御有效性仍是弱证据**：带签名的变更记录能证明转移链条，并不能证明内容真实；单个产品或研究原型的治理接口也不是端到端安全保证。

### 5. “记住什么”从对话片段分化为不同状态对象

同样叫作长期记忆的对象，现在已经明显分叉。MemP 将轨迹编译为可复用的指令或脚本；MemSkill 与 XSkill 分别讨论记忆操作本身的技能和从经验到任务技能的抽象；Collaborative Memory 区分私有与共享片段及其来源；POLAR、WorldLines、MeMento 则把个性化多模态概念、部分可观测世界状态与多模态压缩带入记忆系统。[MemP](https://arxiv.org/abs/2508.06433) [MemSkill](https://arxiv.org/abs/2602.02474) [XSkill](https://arxiv.org/abs/2603.12056) [Collaborative Memory](https://arxiv.org/abs/2505.18279) [POLAR](https://arxiv.org/abs/2605.26256) [WorldLines](https://arxiv.org/abs/2606.18847) [MeMento](https://arxiv.org/abs/2608.01456)

这支持一个**有条件但很实用的分类判断**：事实、经历、程序、身份/偏好、项目状态和世界状态的更新规则、权限和错误形态不同，不能只用一个“向量化文本块”概括。它不支持把这些路线按单一分数排序；多数工作仍使用各自的任务与评价协议。

## 过去 90 天：值得跟踪，但尚未升级为定论

90 天窗口（2026-05-13 至 2026-08-10）最密集的新材料并非单一架构，而是几组彼此呼应的提案。下表中的“信号强度”描述证据位置，不是技术推荐。

| 90 天信号 | 为什么进入观察 | 当前强度与限制 |
|---|---|---|
| 原子事实—事件—时间档案，以及双时间版本 | 让事实身份、有效时间、修订时间穿过写入与读取链 | **有条件信号**：机制清晰；效果有任务间反向结果 |
| 学习型控制器、预算感知巩固、事务边界、遗忘位置 | 将写、改、合并、删除视为可选择且可恢复的动作 | **有条件信号**：多份近期工作出现；独立复现与长期安全性不足 |
| 主动导航与可信检索 | 把读时选择从纯相似度扩展到路径、范围和信任 | **弱至有条件信号**：设计方向明显，尚未形成可比的普遍收益 |
| MAFIA、Salami、MutMem、DP-MemView、STALE | 细化攻击、隐私、变更可追溯和状态更新后的行为陈旧 | **威胁已确认；防御仍弱**：研究多数为预印本或原型 |
| 动作、共享、多模态和安全生命周期基准 | 使“记住了”不再等于“答对了” | **确认性分化**：任务族增加，但尚无统一可比总分 |

这些变化之所以不能直接称为“领域已经转向”，有三个原因。第一，窗口内大量材料是预印本，发布时间只能证明出现，不能证明复现、使用或成熟。第二，不同论文常改变模型、数据、检索器、上下文预算和评测单位，结果不宜横向拼接。第三，新的仓库或高关注度项目首先只是调查线索，除非有固定版本、代码表面、维护和独立使用证据，不能作为工程成熟或采用的证明。

## 工程侧的新近性：有活动信号，没有增长排行榜

定向补查的 [`openai/codex` 本地 Memory](projects/openai--codex.md)提供了一个比普通 Memory SDK 更接近当前 Coding Agent runtime 的公开实现：LLM 负责两阶段形成与全局巩固，SQLite 负责候选/job/使用反馈，Markdown 与 Git baseline 负责可检查的持久工件，读取则采用 2500-token 常驻摘要加词法渐进展开。它确认“控制面、项目状态、生成式 Memory 与权威规则分层”已经进入现役工程，同时也显示全局 scope、生成式 conflict/delete、并发 selection 和后台成本仍未完全闭环。

v09 对 59 个候选仓库做了截至 2026-08-10 的状态观察：其中 19 个创建于 90 天窗口内，39 个创建于过去 12 个月，54 个在 90 天窗口内有推送。该样本显示工程实现正在快速分化到上下文压缩、程序/技能、个人状态、编码项目图、可移植资产、安全拦截和细分评测等表面，但它只证明在该观察时点存在这些项目及活动，不能证明质量、生产采用或增长速度。[完整雷达与方法限制](../../agent-memory-v09/bundle/reports/06-github-trend-radar.md)

这里刻意不列“星标增长榜”。本底稿中的 GitHub stars 是同一轮单次快照；公开历史也不足以为绝大多数候选恢复可比的时间序列。单点累计 stars 可以提示关注，却不能推出增长、加速度、技术质量或采用。这个限制同样适用于新建仓库：新不等于重要。

## 仍未改变的事实

近期材料没有消除几个根本不确定性。结构化 memory 是否优于原始历史，依赖检索器和 token 预算；版本化提高更新可见性，不一定提高时间推理；写入成功不表示后续行动已经改变；来源链不等于内容真实；而不同 benchmark 的高分也不构成同一能力的证据。

所以，当前最可靠的结论不是“某种新 memory 已经胜出”，而是这个领域正在把以前混在检索里的状态语义、生命周期、权限、修复和行动后果拆开。哪些组合在同一任务、同一预算、同一安全约束下真正更好，仍缺跨后端的独立比较。
