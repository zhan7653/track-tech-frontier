# 当前实践与近期信号

## 当前已稳定的主流

- **Markdown 作为作者层，静态 HTML 作为分发层。** Quarto、MyST、MkDocs、Observable 都保留文件化源内容并在构建阶段派生站点。
- **跨页导航 + 页内目录 + 搜索。** 大型套件不再依靠一张手写目录；页面层级和全文索引由构建结果生成。
- **技术构件进入标记语言。** 图、表、数学、代码、引用、交叉引用和 callout 不再只是原始 HTML 拼接。
- **可逆增强。** 标准 HTML 结构、静态输出和打印仍是底座，交互负责更快定位或探索。

## 最近 12 个月出现的变化

本次 GitHub 观察里，`tech-route-maker`、`research-forge`、`research-article-template`、ReActicle 和 `beautiful-article` 所在的 skills 仓库均在最近 12 个月创建。共同信号是：AI 生成的研究内容开始被约束为结构化模型、语义组件或可验证交付，而不是让模型自由写一整页 HTML。

这仍然只是“实现表面扩大”的信号。仓库创建、提交与 Star 不能证明设计有效、维护稳定或被生产采用。

## 最近 90 天的弱信号

- ReActicle 把“主题”定义为 CSS 令牌与作者约束的双重合同，并强调单文件离线输出。
- `tech-route-maker` 把每个可见图节点绑定到来源和定位信息，再导出 HTML/SVG/PPTX 等多种表示。
- `research-forge` 的规划材料把证据表、PRISMA、HTML 报告和可追溯性放进同一研究工作台设想。

它们的方向值得吸收，但不应把早期项目的组件名称或工程栈固化进本仓库接口。

## 没有变化的基本约束

交互文章的制作与审阅成本仍高；动态内容仍可能逃出搜索、打印和无障碍树；离线单文件和多页可维护站点仍有体积与更新粒度的取舍。新框架没有消除这些问题，只是在重画边界。
