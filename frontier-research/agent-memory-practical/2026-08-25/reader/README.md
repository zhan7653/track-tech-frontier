# 读者入口

这套报告从 TencentDB Agent Memory 与 Codex Local Memory 的固定实现出发，形成六层 Agent Memory 架构：输入、写入与形成、状态/存储/索引、管理与演化、读取与上下文、反馈/经验/持续学习。

## 推荐阅读顺序

1. [六层总览](overview.md)：先看一条完整数据流和六层各自承担的工作。
2. [第 1 层：输入](01-input.md) 到 [第 6 层：反馈与持续学习](06-feedback-learning.md)：依次看 TencentDB、Codex 与对应前沿案例。
3. [Codex 完整工程说明](codex-complete.md)：从固定 commit 重建组件、数据库、文件工件、读取路径、反馈和限制。

主阅读路径只有上面的总览、六层正文和 Codex 完整说明。`architecture.md`、`trends.md`、`github-radar.md`、`scenarios.md` 等文件是兼容/导航入口，不代表还有一组未完成的主章节。

## 每章的阅读方式

前五层优先从 TencentDB 的具体实现开始，再写 Codex 与指定前沿案例。第六层先极简说明两套仓库的短反馈链，随后每篇论文/仓库按自己的机制单独展开。第五层的每条读取路径都说明进入方式、检索方式、输出形态和上下文位置。

## 证据标记

- **代码事实**：来自固定 commit、官方仓库或可定位的实现路径。
- **官方说明**：来自项目文档、发布说明或 issue；issue 只表示问题报告。
- **论文/原型**：来自论文原文或作者提供的代码，结果只适用于论文给出的协议和数据。
- **报告判断**：在前述材料基础上的限定性归纳。

论文和原型会明确写出成熟度。GitHub Star 只用于去除明显低关注噪声，不承担质量、性能或生产采用证明。
