# 展示架构：权威 Markdown 与可重建 HTML 之间增加语义层

## 总体结构

```text
reader/**/*.md + 本地资源
        │
        ▼
安全 Markdown 解析器
（块结构、内联、链接、标题、表格、代码、Mermaid）
        │
        ▼
语义中间模型
（页面类型、标题树、阅读时间、外链、图节点/边、搜索文本）
        │
        ├──────────────┬────────────────┐
        ▼              ▼                ▼
多页 HTML         搜索索引 JS       build-manifest.json
        │
        ▼
共享 CSS/JS：套件导航、页内目录、专注模式、主题、复制、打印
```

这条链路故意把“解析内容”和“设计页面”分开。解析器只生成受限语义节点，模板不能从 Markdown 执行任意脚本；导航、索引和图解都从同一模型派生，因此相对链接、标题锚点和搜索位置可以一起验证。

对这个仓库，最耐久的生成边界是“Markdown 权威源 → 受限语义中间模型 → 静态 HTML/索引/清单”，而不是把每份报告手工重写成框架组件。

## 构建阶段

1. **发现页面。** 只读取 `reader/` 与明确允许的入口文件，保持相对目录结构；`README.md` 映射为目录 `index.html`。
2. **解析和校验。** 识别 GFM 常用块、标题层级、表格、围栏代码和 Mermaid；原始 HTML 一律转义。
3. **建立套件地图。** 根据稳定路径把总览、机制、场景、横切和项目分组，同时允许未来用一个小型配置文件覆盖顺序和标签。
4. **派生解释组件。** Mermaid 生成 SVG 与文本后备；表格套上滚动容器；代码块附语言与复制按钮；外链显示域名。
5. **生成检索。** 以页和章节为粒度写入静态 JS 数据，避免 `file://` 下依赖 `fetch()`。
6. **写出清单。** 记录输入、输出、UTF-8 字节哈希和构建参数，供回归和发布核查。

## 页面运行阶段

页面脚本只负责可逆增强：打开/关闭导航、过滤搜索结果、更新当前章节、复制代码、切换主题和专注模式。关闭 JavaScript 后，正文、链接、表格、SVG、标题和打印仍应存在。

源报告可能包含抓取内容、模型生成文本和外部链接；HTML 生成器必须转义原始标签并只允许明确的安全 URL 协议，不能把 Markdown 当作可信脚本输入。

## 图解的双层表示

当前示例里有五个 Mermaid 流程图。生成器应保留三层：原始代码用于再编辑；解析后的节点/边用于文本摘要；SVG 用于视觉关系。若某种 Mermaid 语法超出内置子集，页面显示可读代码和明确的“未渲染”状态，而不是空白。

## 失败边界

- 标题重复：生成确定性后缀并在清单中告警。
- 相对链接目标不存在：构建失败，不能留到浏览器 404。
- 非 UTF-8 或替换字符：构建失败。
- 超宽表格：允许横向滚动，打印时缩小而不是裁切。
- JavaScript 关闭：搜索和按钮失效，但内容与导航链接仍可达。
- CSS 不支持新特性：设计令牌提供普通颜色回退，不依赖 `color-mix()` 才能辨认状态。

## 为什么不直接采用一个现成框架

Quarto、MyST、MkDocs Material 和 Observable 已证明层级导航、检索、交叉引用、图表和内容组件的价值，但它们也各自带来 Pandoc、Node/React、MkDocs 主题或数据应用运行时。当前仓库的脚本明确保持 Python 标准库依赖；先实现所需机制，未来再提供可选适配器，比把作者工作流整体迁入某个框架更可逆。
