# 安全、隐私与治理：Memory 不是可信知识库，而是一条可被长期利用的输入链

Agent 把文本、工具输出、网页、环境观察和他人贡献保存下来后，攻击者不必在当前轮说服模型；他可以等待某个触发条件，让较早写入的内容在未来被读出并影响行动。安全问题因此贯穿 `write → manage → read → act`，而不是给向量库加一层访问控制就结束。

本文的描述性判断以 2026-08-10 的已核验证据为界。研究与工程控制都很活跃，但没有一条已被独立证明的端到端生产闭环。

## 从一次网页观察到一次错误行动

```text
外部文本、工具输出、用户/Agent 贡献
      │ write：身份、来源、scope、风险判定
      ▼
隔离区 ──► 准入记录 ──► 版本化 memory / 派生摘要 / 技能
                              │ manage：签名、谱系、撤销、删除、回滚
                              ▼
查询 ──► scoped retrieval ──► context view ──► action authorization ──► 工具/外部世界
             read：最小披露、      │                   │
             注入检测、冲突标记    └── audit / incident / repair ──────────┘
```

关键区别在于：**被保存**不等于真实，**有签名**不等于无害，**可读取**也不等于有执行权限。一个合法用户的正常文本仍可能在模型解释后变成危险指令；一个访问控制正确的检索结果仍可能泄露不该出现在回答中的内容。

## 风险与控制的方案家族

| 方案家族 | 主要作用阶段 | 解决什么 | 不能单独解决 | 成熟度 / 反证 |
|---|---|---|---|---|
| 写入检测与隔离 | write | 已知投毒、格式/策略违规、可疑来源 | 未来触发、组合攻击、合法内容的恶意语义 | 工程常见；漏报/误报及绕过仍是核心问题 |
| provenance、签名与版本谱系 | write/manage | 谁在何时写入、派生自何物、如何定位回滚 | 内容真假、授权主体被诱导 | 机制成熟度中等；MutMem 明确不把可追溯性当真值证明 |
| scope / IAM / capability | write/read/act | 用户、租户、会话、Agent 与工具权限隔离 | scope 内的污染、模型对权限的误用 | 基础能力较成熟；Memory 专用语义仍不统一 |
| 最小披露视图与隐私变换 | read | 降低模型/响应接触原始敏感内容 | 非响应通道泄漏、多轮推断、错误派生物 | 研究活跃；效用—隐私边界未稳定 |
| 检索/组合阶段防注入 | read | 把不可信记忆与指令层分开、检测间接指令 | 新型语义绕过、召回外通道 | 仍早期，必须与写入和行动控制配合 |
| 行动时再授权 | act | 高风险工具调用不因“记忆说了”而自动获权 | 已泄露信息、低风险长期操纵 | 原则广泛接受；统一 Agent Memory 测法不足 |
| snapshot、依赖图与派生物修复 | manage/repair | 找回某版存储，追溯污染传播 | 未记录依赖的摘要、技能、cache 与外部副作用 | 工程必要但端到端验证稀少 |

## 每一段都需要问不同的问题

**写入。** 需要识别来源、主体、租户、会话、时间和写入理由；不确定内容可先进入隔离区。`AgentPoison` 说明很小比例的恶意文档即可改变 RAG/Agent 行为，之后出现的 MINJA、eTAMP 把入口扩展到查询、观察和环境压力，而不只是一条显式的 store write。[AgentPoison](https://arxiv.org/abs/2407.12784)

**管理。** 合并、摘要和“轨迹晋升为技能”会产生新的攻击面：一条原始内容被清除，并不意味着它已从摘要、embedding、profile、cache 或技能中消失。能记录 predecessor、派生关系和策略决策的谱系有助于定位修复范围；它不判断内容是真是假。近期的 `MutMem` 与隐私视图工作说明这一层正在从“审计日志”扩展到可验证更新与受控展示，但作者协议尚不能证明跨系统的效用或安全优势。[MutMem](https://arxiv.org/abs/2608.02843) [DP-MemView](https://arxiv.org/abs/2608.03130)

**读取。** 检索必须同时看语义相关性和主体、用途、时间、敏感级别；返回给模型的内容应保留来源与不确定性，而不是伪装成系统指令。只靠向量相似度会把“最像的文字”当成“此时可披露的证据”。查询侧与组合侧攻击的重要性在于，它们可绕过静态写入扫描。

**行动。** Memory 是证据输入，不是能力令牌。工具调用仍要基于当前主体、动作类型、目标和风险做授权；高价值操作尤其不能因为一段检索文本、签名记录或模型摘要而跳过这一关。`STALE` 类型的负面证据也提醒：存储层已更新不代表 Agent 行为已停止遵循旧状态。

## 评测数字为何不能直接比较

安全论文常报告“攻击成功率”，却可能测量不同阶段。AgentPoison 的攻击成功率、Sleeper 的成功取回条件下恶意行动比例，以及技能演化研究的持久工件修改率有不同分母；它们不能排序。`MemSecBench` 的贡献是显式覆盖 Write–Execute–Forget，而不是制造一个可与普通 QA 比分的安全总分。[MemSecBench](https://arxiv.org/abs/2607.27080)

| 应观察的量 | 对应阶段 | 含义 |
|---|---|---|
| poison admission / detection | write | 恶意或不合规内容是否进入可用 store，正常内容损失多少 |
| lineage completeness / repair reach | manage | 是否能找到所有派生物并证明删除、回滚或重建范围 |
| unauthorized inclusion / injection success | read | 不该出现或带有操纵意图的内容是否进入上下文 |
| harmful-action / refusal correctness | act | Agent 是否在触发下执行不该执行的工具行动，或误拒绝正当操作 |
| privacy leakage / utility | read/act | 机密是否被抽取或推断，同时是否损害正当任务 |
| p95 policy、repair 与审计成本 | 全链路 | 控制是否在真实压力下仍可运行 |

`MEXTRA` 的黑盒私密信息抽取和后续针对 Memory 的攻击表明，“不显示原文”不足以消除推断与多轮泄露。与此同时，实验攻击通常不涵盖真实企业身份、长期用户纠正权、外部副作用和完整 incident response；因此既不能把作者 ASR 视为现实风险概率，也不能把一次通过的 demo 视为安全保证。

## 当前主流、近期变化与未解问题

当前较稳固的共识是：持久化把风险从单次提示扩展为生命周期风险；写入、读取和行动应分段控制；来源、版本、scope 和审计是基础设施；敏感行动不能仅信任“来自 memory”。

近 12 个月，研究从 RAG 投毒扩展到间接写入、检索后执行、遗忘/修复与技能晋升；近 90 天的信号包括 `MemSecBench`、查询/组合攻击、签名更新和差分隐私视图。它们提示问题面变宽，却尚未形成可跨系统复现的统一防御协议。

仍不知道的包括：如何量化“原始记录已删但派生物仍在”的完整删除；在共享 Memory 中如何同时处理动态撤销、跨租户引用和投毒；防御成本在高并发或长时间任务下如何变化；以及模型原生/隐式记忆能否接受与外部 store 相同的删除和审计要求。这些不确定性会直接影响人们对“治理已覆盖”的判断，而不是只影响某篇论文的分数。

## 证据与阅读边界

- 投毒入口与攻击基线：[AgentPoison](https://arxiv.org/abs/2407.12784)。
- 生命周期安全评测：[MemSecBench](https://arxiv.org/abs/2607.27080)。
- 可追溯更新与隐私视图的近期研究：[MutMem](https://arxiv.org/abs/2608.02843)、[DP-MemView](https://arxiv.org/abs/2608.03130)。
- 工程控制面仅作实现实例：OWASP 的 [Agent Memory Guard](https://github.com/OWASP/agent-memory-guard) 描述检测、策略、snapshot 与审计，但不是独立的生产安全验证。

本文呈现控制边界、反证与成熟度，不构成特定产品的安全配置或上线建议。
