# Update Mode

Read the prior run, research plan, corpus entities, clusters, repository observations, trend metrics, deep evidence, syntheses, gaps, and reader suite before searching.

1. Preserve the user contract unless the user changes it, but allow the taxonomy and derived research questions to evolve.
2. Search from the prior as-of through the new as-of with overlap for delayed indexing; also rerun rolling 90-day and 12-month discovery so newly indexed old work is visible.
3. Recheck mutable repositories, releases, standards, products, benchmarks, withdrawals, corrections, and migration/deprecation status.
4. Append dated repository observations rather than overwriting them. Recalculate momentum only when the observation history supports it.
5. Classify entity changes as `new`, `updated`, `corrected`, `withdrawn`, `renamed`, `superseded`, `reclassified`, or `newly-discovered-old`.
6. Re-run mapping and cluster merge/split review. A new item may create a cluster, move a boundary, or change an entity's memberships.
7. Reopen every proposition, consensus assessment, trend signal, and executive conclusion touched by changed evidence. Preserve prior minority and contradictory evidence.
8. Deeply verify material new entities and any old entity whose current state changed. Do not force the complete old discovered corpus through deep verification.
9. Produce a full current suite plus a delta that separates corpus, map, trend, evidence, consensus, and decision changes.
10. Preserve the prior bundle unchanged and link it from the new run.

An update is not merely an appended bibliography. If the map, consensus, or engineering state changes, rewrite the affected cluster and top-level synthesis artifacts.
