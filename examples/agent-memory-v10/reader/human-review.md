# 可选人工评审：只处理可能改变判断的少量问题

本套件在没有人工评审时也应是完整读者成品。本清单不要求人工补写章节、逐条批准报告，或把不确定性藏进“待定”。每一项都已有当前背景、候选和暂定判断；人工只需决定是否改判、调整重点或触发定向增量深挖。

## 1. 生命周期控制的增益能否跨后端成立？

**背景。** 当前材料支持一个描述性结论：写入准入、版本/冲突处理、巩固和遗忘是长期 Memory 的独立控制问题，不能被“换一个检索器”完全替代。但不同工作使用不同模型、任务、上下文预算和后端，现有结果无法给出跨系统的可比提升幅度。

**候选。**

- 把 lifecycle control 视为当前架构共识，但不谈统一效果增益；
- 把它降为只适用于复杂、可变状态的路线；
- 若有可比独立实验，再把某些子机制的效果表述收紧或增强。

**暂定判断。** 第一项最符合现有证据：控制面在机制和工程叙事中反复出现，但性能收益仍证据偏弱且条件化。

**为何值得人工介入。** 这个判断会影响总览中“Memory 不只是检索”的力度，也会影响写入/生命周期专题应占的篇幅。

**触发的增量深挖。** 若评审者需要更强结论，定向搜集同一任务流、相近模型与预算下，对 flat/vector、hybrid 和 lifecycle-aware 系统的消融、独立复现与成本记录；按协议指纹分组，不跨组排名。

## 2. 图、时间与版本化表示的代表性边界

**背景。** 关系、时间、来源、版本和冲突处理能解决 flat similarity retrieval 难以表达的状态问题；但“图记忆”覆盖从轻量实体关系到昂贵的图构建和导航，不能把它当作一个性能或成熟度一致的家族。

**候选。**

- 以“结构化/时态/版本化表示”为主标题，将图导航列为一支实现路线；
- 以“图记忆”作为对外主标签；
- 拆出关系表示与时态/版本控制两个专题。

**暂定判断。** 第一项最稳妥：它保留图方法的信息量，又不会把数据模型、索引和检索策略混为一谈。

**为何值得人工介入。** 这是读者地图的命名与边界问题；不同读者关心的系统形态不同，可能影响专题拆分而非事实真伪。

**触发的增量深挖。** 若需要拆分，分别补查多跳/关系问答、as-of/冲突解析与版本回滚的工程实现、基准任务和反例，并检查它们是否共享可比较的定义与协议。

## 3. 最近 90 天的项目与论文：何时从弱信号升级为主线？

**背景。** v09 已把近 90 天材料纳入冻结地图，但新项目、预印本和单次仓库快照通常只能证明“值得关注”，不能证明生产成熟、性能提升或增长趋势。读者版必须把这些信号放回机制脉络，而不能以“最新”取代证据。

**候选。**

- 保持“弱信号”标记，除非出现独立复现、稳定维护或明确的机制增量；
- 因近期注意力提高而提升为主流路线；
- 在指定应用场景中单独高亮，但不提高总体成熟度。

**暂定判断。** 第一项是默认：近期性只决定补查优先级，不自动改变领域地位。

**为何值得人工介入。** 如果读者的重点是快速变化的 Coding Agent 或多 Agent 实践，第三项可能改变趋势页和工程案例的篇幅。

**触发的增量深挖。** 重新抓取明确候选的 release、fixed commit、维护/issue 信号、独立集成与可比评测；保存至少两个带日期的观察后，才讨论增长或加速。

## 4. 共享 Memory 的“可移植性”应写到什么程度？

**背景。** 共享、分布式和可移植 Memory 已有协议、服务和仓库候选，但公开材料对跨实现 round-trip、schema 兼容、权限传播和真实组织部署的独立证据有限。把接口存在写成互操作已经成立，会超出证据。

**候选。**

- 将其描述为活跃工程方向，明确互操作与治理保证仍证据薄弱；
- 将协议接口的存在视为已成熟互操作；
- 因缺少公开采用材料而降为纯研究问题。

**暂定判断。** 第一项最符合现有材料：方向与实现真实存在，但端到端的可移植性和授权语义尚未得到足够独立验证。

**为何值得人工介入。** 该措辞会影响多 Agent 场景的风险理解，也决定是否需要投入进一步标准与实现兼容性检查。

**触发的增量深挖。** 指定一个或多个协议/实现后，核对规范状态、版本、独立实现、round-trip 或 conformance 工件、ACL/删除传播语义与真实部署证据；若证据仍只来自项目方，保持有界表述。

## 评审结果怎样进入下一版

人工结论应记录为增量：说明审的是哪一项、采用哪个候选、依据的新证据或场景优先级、受影响页面，以及结论从何种措辞变为何种措辞。未被评审的项目继续沿用这里的暂定判断；不能因为未评审就让相关读者正文留下空白。
