# Agent Memory 场景视图：同一套机制怎样面对不同状态

应用场景不会创造一套完全不同的 Memory 原理，但会改变记忆对象、更新速度、权限边界和最终使用方式。本页将四个重要场景放在同一坐标中，帮助读者进入相应专题；它描述公开系统中的组合形态，不提供实施建议。

| 场景 | 主要对象 | 写入特点 | 管理难点 | 读取与使用 | 最突出的风险 | 专题 |
|---|---|---|---|---|---|---|
| 个人助手 | 对话事件、偏好、关系、承诺、身份属性 | 从自然语言持续抽取，观察与推断易混 | 纠正、过期、跨域用途与删除 | 个性化回答、提醒与工具参数 | 隐私、错误画像、身份漂移 | [个人助手](scenarios/01-personal-assistants.md) |
| Coding Agent | 代码结构、任务、决策、构建结果、工具和环境状态 | 来自文件、git、terminal、issue 与会话 | 仓库/分支/提交作用域和快速变化 | 代码搜索、计划、修改、测试与交接 | stale code、秘密、错误项目规则 | [Coding Agent](scenarios/02-coding-agents.md) |
| 多 Agent | 消息、任务、共享工件、经验与组织规则 | 多主体并发写入，来源和权限不同 | 冲突、合并、撤销、传播和可移植 | 协作、委派、复用与共享行动 | authority collapse、污染和租户泄露 | [多 Agent](scenarios/03-multi-agent-shared-memory.md) |
| 世界状态/具身/多模态 | 对象、位置、观察、地图、动作结果、图像与视频事件 | 部分可观测且多模态、时间密集 | 状态漂移、空间对齐、遮挡和压缩 | 导航、规划、操作与持续环境交互 | 旧状态驱动错误行动、模态错配 | [世界状态与具身](scenarios/04-world-state-embodied-multimodal.md) |

## 场景差异真正改变了什么

### 状态有效期

用户的稳定偏好可能跨月有效，代码环境可能在一次提交后立即变化，世界状态则可能在数秒内过期。相同的检索分数不能表达这些差异；时间和版本语义必须来自对象和写入模型。

### 权威来源

个人助手中的用户纠正、Coding Agent 中的仓库和测试结果、多 Agent 中的角色与共享规则、具身系统中的新观察具有不同权威。Memory 若只保存内容而不保存来源，就会把推断与事实、旧观察与当前状态、私有经验与共享规则混合。

### 行为接口

对话记忆常影响回答风格和事实选择；项目记忆约束文件修改和工具调用；程序性经验可能直接生成行动步骤；世界状态进入导航和控制。越接近外部行动，适用条件、权限和失败恢复越不能依赖模型临场猜测。

### 评价终点

个人助手关注纠正后的连续性和隐私，Coding Agent 关注代码与任务结果，多 Agent 关注协调和隔离，具身系统关注在不完整观察下的行动成功。把这些场景压成一个 recall 分数会失去问题本身。
