# 评估框架：展示是否真的帮助理解

## 不是打分表，而是失败门槛

| 读者任务 | 可观察证据 | 硬失败 |
|---|---|---|
| 从入口解释领域地图 | 首页与 overview 在一次短读内给出问题、机制、关系和近期变化 | 入口只是文件清单 |
| 找到某个技术概念 | 搜索命中页与章节，键盘可操作 | 只能浏览目录树 |
| 重建一个机制 | 图、正文和表格对同一状态/数据流给出互补解释 | 图只是装饰或空白 |
| 比较方案家族 | 表格可读、可横向滚动、表头保持上下文 | 移动端裁切列 |
| 检查证据 | 外链、来源域名和上下文靠近结论 | 来源只在独立长列表 |
| 离线/无脚本阅读 | 直接打开 HTML 仍有正文、图、链接和导航 | 关键内容依赖网络或 JS |
| 打印归档 | 页面断行、表格和图不被裁切 | 打印隐藏正文或展开内容 |

## 浏览器验收矩阵

至少检查桌面 1440×900、窄桌面/平板 900×800、手机 390×844，以及打印预览。每轮记录首屏、长页、表格、Mermaid、搜索、键盘焦点和断链状态。

## 与论文证据的关系

Idyll 的首次使用结果说明受约束标记与组件接口可以降低作者门槛，但没有证明某个具体导航或主题提高本仓库读者的理解。EMAR 强化了“正文无需交互也成立”的边界，但其分析选择控件不能直接推广到没有可操作变量的机制报告。因此本项目采用任务验收，而不虚构一个综合可用性分数。
