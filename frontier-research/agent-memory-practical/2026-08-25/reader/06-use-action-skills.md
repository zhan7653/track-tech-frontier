# 第 6 章　使用、行动与技能：记忆怎样进入下一次工作

## 结论

Memory 的价值最终要落在当前任务的判断和行动上：帮助 Agent 少走一次已经走过的弯路、遵守已知约束，或复用已经验证过的步骤。这个过程至少跨过三道边界：找出相关材料、判断它是否适用于当前环境、在当前权限下决定是否行动。

Codex 的本地实现把前两道边界做成“常驻摘要 + Agent 主动查找”的文件阅读流程；Memory 只能提供上下文，不能授予文件、网络、凭据或支付权限。若 Agent 实际使用了 Memory，还需在最终回答中给出可解析 citation，系统才会将这次使用回写到候选记录。这个回写是第 7 章的起点。

## 6.1 从 Codex 抽出的行动前数据流

固定代码快照中的 Codex 有两种可读状态：`memory_summary.md` 随新线程进入提示词；较详细的 `MEMORY.md`、`rollout_summaries/` 与 `skills/` 留在本地 Memory 根目录中，供主 Agent 在需要时查找。读取端提供 list、read、search 和 ad-hoc note 等受限接口；本地 search 做的是文件内容的词法扫描，不计算 embedding 相似度或 ANN 距离。[固定版本读取接口](https://github.com/openai/codex/blob/c9b19deb09c1841ce7acc33ddb96276030936a29/codex-rs/ext/memories/src/backend.rs)

```text
当前任务 + memory_summary.md
          ↓
Agent 判断是否需要历史证据
          ↓
按关键词搜索 MEMORY.md / summaries / skills
          ↓
读取命中的行与其来源线索
          ↓
检查当前项目、工具版本、权限与任务条件
          ↓
形成回答或工具行动候选
          ↓
当前 sandbox / approval 决定能否实际执行
```

这条链路解释了一个容易被忽略的事实：Memory 影响行动的方式，通常是改变 Agent 的“下一步选择”。当前环境的授权检查仍然独立存在。Codex 即使读到“上次用这个命令成功”，仍然要在当前工作目录、当前 sandbox 和当前审批规则下运行命令。

| 环节 | Codex 当前做法 | 对行动的影响 | 不能保证的事 |
|---|---|---|---|
| 常驻线索 | 注入 `memory_summary.md` | 让 Agent 知道哪些项目或任务族值得继续查 | 摘要本身不等于完整证据 |
| 深读 | 对本地文件做词法搜索、按行读取 | 把详细步骤、错误文本和 rollout 线索逐步带入上下文 | 关键词写得不好时会漏召回 |
| 形成行为 | Agent 结合当前任务自行推理 | 可调整工具、参数或回复内容 | 没有确定性“技能自动执行”路径 |
| 真正执行 | 现有 sandbox、权限和 approval | 防止 Memory 直接越过行动边界 | 不证明读取内容本身正确 |

## 6.2 一个 Coding Agent 的具体例子

假设 `MEMORY.md` 中有一段由过去 rollout 巩固而来的项目经验：

```text
项目：payments
适用条件：refund integration tests
经验：若 fixture 仍使用 refund_status，先迁移为 refund_state，
再运行 cargo test -p payments --test refunds。
来源：thread T-1842；rollout summary: payments-refund-fixture.md
```

当前用户只说“修一下退款测试”。Agent 的合理使用链应当是：

| 步骤 | Agent 看到的内容 | 合理动作 | 不应直接推出的结论 |
|---|---|---|---|
| 1 | 常驻摘要中有 `payments/refund` | 搜索 `refund fixture` | 当前失败一定还是同一原因 |
| 2 | 读到上述经验和来源 | 检查仓库中的实际 fixture 与报错 | 可以跳过测试或直接改文件 |
| 3 | 当前 schema 已确认变化 | 提出/执行受限修复，再跑指定测试 | 这个步骤适用于所有 payment 项目 |
| 4 | 测试结果 | 在回答中说明实际验证结果 | 成功一次就把规则升级为全局技能 |

这里的 Memory 让 Agent 更快产生一个可检验的假设。真正的证据仍来自当前文件和测试；当前工具权限也仍然独立生效。

## 6.3 “经验”“流程”和“技能”处在不同位置

把所有可复用内容都叫 skill，会掩盖风险差异。以下层级更接近当前工程形态：

| 可复用对象 | 内容形状 | 在当前任务中的用法 | 最低限度的控制信息 |
|---|---|---|---|
| 轨迹 | 观察、工具调用、结果、失败日志 | 重新阅读相似经历 | 来源、时间、环境、结局 |
| 反思 | 对失败原因或规律的自然语言说明 | 作为注意事项进入计划 | 支持它的尝试、反例、适用范围 |
| 流程 | 有步骤、分支和恢复方法的 playbook | 参数化后执行或建议执行 | 输入输出、工具/schema 版本、前置条件 |
| 可执行技能 | 脚本、函数、工具模板或 workflow | 产生可运行的行动候选 | 依赖、effect、测试、版本、撤回路径 |
| 管理技能 | 形成、检索、合并和遗忘 Memory 的规则 | 改变 Memory 操作本身 | 可操作范围、日志、预算、回滚 |

Codex 当前的 `skills/` 属于受 Phase 2 维护的文件工件，但固定代码没有提供“检索到一个 skill 就自动执行”的通用权限通道。它更接近可被 Agent 进一步阅读和采用的操作手册。这个设计保留了行动前的人工/运行时判断空间，也意味着技能是否真的提升了任务结果，不能只凭文件存在来判断。

## 6.4 近期工作补充了什么

### 经验如何晋升为可复用流程

[MemP](https://arxiv.org/abs/2508.06433)（2025-08，历史背景）将原始 trajectory、逐步 instruction 和更高层 script 分开构建、检索和更新；[AFTER](https://arxiv.org/abs/2606.23127)（2026-06，预印本）将程序性记忆的迁移拆成跨任务、跨角色和跨模型等维度。两者共同追问：一段经验离开原环境后，是否还保持适用。MemP 超出本报告的半年前沿窗口，保留它只为解释当前“经验→流程→技能”的来源。

这种路线会在晋升时补上对象字段：成功与失败样本、输入条件、工具/API 版本、可变参数、已知反例和测试。它尚主要是论文中的机制与作者评测；不能据此认为一般的 Agent 已具备可靠的自动技能编译。

### 行动要测工具参数，而不只测回答

[Mem2ActBench](https://arxiv.org/abs/2601.19935)（2026-01，历史基准，超出半年窗口）包含 2,029 个 session 与 400 个工具使用任务，考察历史中的长期约束能否进入工具选择和参数。它对应的缺口很明确：一段 Memory 被正确召回，仍可能没有改变 Agent 的实际操作。近 90 天的 [MemTX](https://arxiv.org/abs/2607.23929)（2026-07，预印本）把这个缺口再往前推进：工具调用要等当前 belief 通过权限、来源和有效性检查后才放行，并对撤回信念触发的派生影响做级联修复。

例如，历史要求“发票必须发送到审批邮箱”。答复中复述这条规则不够；测试应检查 Agent 调用发信工具时是否填入正确收件人、是否在资料不足时停下。这是作者提供的基准证据，描述的是指定任务协议，不能当作生产行动安全的证明。

### 自演化技能把晋升点变成攻击面

2026 年 8 月的 [PoisonedEvolution](https://arxiv.org/html/2608.05563v2) 检查不可信 trajectory 怎样被自我演化流水线提炼并保留为技能。论文将过程拆为恶意内容被纳入、被归因到演化结果、以及后续工件实现目标等阶段。

它给工程带来的直接要求是：未验证轨迹不能因“看起来成功”直接升为可执行资产；技能的 promotion 要保留来源、适用条件、验证记录与撤回链。该研究采用作者构造的惰性 canary 任务，测量的是持久工件被修改等阶段性结果，不能据此估算现实环境中的有害行动发生率。

## 6.5 评估使用是否真的改变了行为

一套可信的评测至少把下面几件事分开：

```text
历史是否被找到
        ↓
是否被正确理解
        ↓
是否适用于当前任务
        ↓
是否改变工具选择/参数
        ↓
行动是否在当前权限和环境下成功
        ↓
副作用、失败和用户纠正是否被记录
```

`Mem2ActBench` 关注长期条件能否落到工具行动；传统长对话 QA 基准主要覆盖前两步。分数不能合并成一个“记忆能力”。同样，某条 skill 被存进目录不代表它被读过、被正确参数化，或在生产环境安全执行。

## 当前边界

- Codex 的词法搜索清晰、便宜且可引用，但它把大量召回责任交给 Phase 2 的标题、关键词和摘要写法。
- Memory citation 是模型输出协议的一部分；读过 Memory 却漏写 citation，usage 不会被回写。
- 当前全局 Memory root 主要依赖 cwd、branch 和文档组织表达项目范围。Agent 仍可能读到跨项目线索，必须自行做适用性判断。
- 可执行经验需要当前时刻重新检查权限、依赖和环境。Memory 文件不能成为隐含授权。
- 关于“自动晋升的技能在真实工作中长期更好”的独立、跨环境证据仍不足；近期论文主要说明机制、基准或攻击面。
