# Agent Memory 的共识、争议与未解决问题

本页综合各机制和横切专题。这里的“共识”不是按论文数、链接数或 Star 投票，而是看独立机制、实现、Benchmark 和反面证据是否在相同条件下指向一致结论。

## 相对稳固的共识

### Memory 是状态生命周期，不是某种存储的别名

跨会话、会变化并影响后续行为的 Memory，至少涉及写入、持久化、更新、读取和使用。只描述数据库或检索器无法说明冲突、纠正、删除、恢复与行动边界。这个认识已同时出现在研究架构、服务接口、生命周期方法和新的评测任务中。

### 对象、作用域、时间和来源会改变正确答案

一条内容属于谁、何时有效、来自哪里、是否为模型推断，会决定它能否用于当前任务。结构化字段不保证内容真实，却为过滤、冲突处理、纠正和审计提供了模型在最后一步无法可靠补回的上下文。

### 访问正从单一路线转向组合

语义向量、关键词、字段、图和时间索引解决不同类型的查询失配。公开实现和研究中更常见的是混合使用，而不是一个访问方式在所有任务上取代其他方式。组合带来的排序、预算和维护问题也因此成为新的工程表面。

### Memory 必须通过后续行为评价

召回命中不等于回答正确，更不等于工具行动正确。近期 Benchmark 将更新、纠正、工具参数、长期可靠性、安全和删除纳入评测，反映出领域正在把终点从“记得”移动到“会正确使用”。

### GitHub 是工程一手材料，但不是成熟度捷径

固定版本代码、依赖、架构和维护记录能说明一个方案真实实现了什么。README、Star、目录、测试文件或单次活动快照不能单独证明性能、增长、生产采用、跨租户隔离或安全保证。

## 条件性共识

### 结构化表示在关系、时间和冲突问题上更有表达力

当任务明确涉及实体关系、as-of、版本替代或冲突时，纯文本相似度难以直接表达全部条件。但这并不推出图、时态数据库或任何单个实现对所有任务普遍更好。维护成本和协议差异仍会改变端到端结果。

### 生命周期控制在可变状态中不可忽略

跨会话状态需要处理接纳、更新、替代、巩固、遗忘与恢复，这些责任不会因检索器更强而消失。尚未形成共识的是每种控制机制能够带来多少效果提升，以及在何种复杂度下值得单独实现。

### 原始证据与构造化记忆通常需要并存

原始记录保留细节和可追溯性，事实、摘要、画像和技能提高使用效率。越来越多架构将后者视为可重建投影而非唯一记录；不过完整保留会增加存储和隐私成本，不同场景的平衡仍不一致。

## 主要争议

| 争议 | 支持方向 | 反方或限制 | 当前判断 |
|---|---|---|---|
| 构造/压缩记忆是否优于原始历史 | 降低 token、聚合多条证据、形成稳定对象 | 结果可随 retriever、预算和任务反转，关键细节可能提前丢失 | 条件性、协议依赖 |
| 图与主动导航是否优于混合检索 | 保留关系、支持多跳和动态探索 | 建图与搜索成本高，数据与实验设置不可直接比较 | 有价值但无普遍排序 |
| 学习型控制器能否替代静态策略 | 可按任务和预算选择写入、重检索、合并或遗忘 | 缺独立长期复现，错误操作可能不可逆 | 新兴、证据偏薄 |
| 丰富画像能否稳定提高个性化净效用 | 提供跨会话连续性和偏好条件 | 隐私抽取、错误画像、漂移和奉承风险随状态增长 | 收益与风险共同条件化 |
| 共享 Memory 是否带来稳定协作收益 | 扩大经验复用和任务可见性 | 权限、污染、冲突、撤销和租户隔离缺共同验证 | 活跃工程方向，端到端证据不足 |
| 项目协议是否正在形成互操作层 | 规范、schema、adapter 和测试资产快速增加 | 同版本独立实现、双向往返和生产采用稀少 | 标准化早期、项目层繁荣 |

## 尚未解决的问题长名单

### 1. 全生命周期的可比实验仍然缺失

现有实验往往只测检索、问答、更新或行动中的一段，使用的模型、预算、后端和评价器不同。我们仍难回答：从简单历史或向量检索升级为显式写入、版本、巩固和控制面后，端到端收益、延迟、存储和维护成本分别变化多少。

### 2. 删除和纠正的终点没有统一定义

主记录更新后，旧摘要、embedding、图边、缓存、备份、程序性经验和已经形成的行为依赖是否同步变化，公开系统很少给出完整证明。“搜不到”与“已清除”“不再影响行动”仍常被混用。

### 3. 自动形成的记忆如何避免错误自强化

模型生成的事实、总结和经验可能有误。如果后续系统把它们当作高权重证据，错误会跨会话积累，并被更多成功/失败解释再次强化。来源、置信度、晋升验证和回滚可以降低风险，但没有通用闭环。

### 4. Memory 的权限是否能随状态传播

共享、派生和压缩会产生新对象。原始内容的可见范围、用途限制、撤销和删除要求如何传播到这些衍生物，尤其跨多后端和多 Agent 时，仍缺成熟统一语义。

### 5. 结构化与图表示的维护成本缺少共同量尺

研究常强调关系与多跳能力，但很少在同一协议下同时报告抽取、实体消歧、增量更新、索引重建、存储增长、错误边修复和查询成本。这使表示能力与生命周期代价难以一起判断。

### 6. 程序性经验怎样获得和失去行动资格

技能和程序可能在保存时有效，后来因工具、环境、权限或安全状态改变而失效。适用条件、版本、验证、弃用和行动时重新授权尚未形成统一工程模型。

### 7. 公开工程证据与真实采用之间仍有断层

许多仓库具有真实代码、测试和维护活动，但缺少独立部署、故障、迁移、跨租户、删除传播和长期成本资料。项目方声明与公开代码能够描述实现表面，不能补足运营证据。

### 8. 最近出现的协议缺少独立互操作证明

项目级记录格式、服务规范和可移植目录正在增加。当前仍少见两个独立组织针对同一版本完成的 conformance、双向 round-trip、字段与生命周期不变量损失报告。

### 9. 长期个性化的用户研究不足

公开 Benchmark 多为合成或有限周期任务。真实用户是否能理解、纠正和删除画像，长期个性化是否提高效用同时避免奉承、刻板化和跨域泄露，仍需要更长周期和更清楚的同意边界。

### 10. 新趋势的独立复现跟不上项目增长

最近 90 天大量论文和仓库强化自动管理、项目记忆、共享协议和安全方向，但多数信号尚未经过跨系统复现。新近性说明值得观察，不足以单独改变主流判断。

## 怎样阅读这些未解问题

本页没有替读者排列统一优先级。每个专题已经给出它影响的机制、现有方案为何不足和当前证据强度；只有可能实质改变领域地图或专题篇幅的少数问题进入[人工评审清单](human-review.md)。人工评审不是报告完成的前置条件。
