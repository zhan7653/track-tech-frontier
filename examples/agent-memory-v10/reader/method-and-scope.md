# 方法、证据与范围

## 这份读者版从哪里来

v10 以 [v09](../../agent-memory-v09/README.md) 为研究底稿：其截至日期为 2026-08-10，并保存了广泛发现、映射、深度证据、仓库固定版本检查、负面证据、趋势观察与审计记录。v10 的工作重点是重新组织叙事，使读者先理解问题、机制和方案空间，再按需进入工程例子或审计材料。

本读者层最初建立时没有新增检索；在 2026-08-12 的分支深度修订中，另外执行了一次很窄的论文新近性与机制缺口复核。它补入三项会增强分支解释、但不改变一级领域地图的 2026 预印本：全链路系统成本表征、状态轨迹型数据管理抽象和程序性技能迁移评测。查询、来源、影响和限制记录在 [分支深度增量](../audit/2026-08-12-branch-depth-delta.md) 与 [增量来源表](../audit/sources.jsonl)。这仍不是一次完整更新，也不暗示已重新确认所有会变化的仓库、发布、标准或采用事实。

## 三层读者结构

```text
技术机制主分支
        ↓
应用场景跨分支视图
        ↓
重点 GitHub 仓库工程案例
```

技术机制是主要分析单元：对象和作用域、写入与形成、表示/存储/索引、更新/巩固/遗忘、检索/排序/上下文构造，以及使用、反馈和经验/技能学习。场景页说明这些机制在个人助手、Coding Agent、多 Agent、世界状态或多模态系统中如何被组合、替换或省略；它不重复全部基础说明，也不升级为推荐方案。项目页把少量有代表性的仓库放回相应机制和场景，分析可见组件、数据流、依赖、接口与边界。

评测、安全与隐私、权限与治理、成本与可靠性、可观测性、互操作与工程集成是横切问题：它们约束整条链路，而不是在最后附加的一层功能。

## 分层证据：什么可以支撑什么

v09 把材料区分为三层，v10 保留这个边界：

| 层级 | 作用 | 能否单独支持读者结论 |
|---|---|---|
| 发现（discovered） | 高召回候选和弱信号，用于找方向和补查 | 不能 |
| 映射（mapped） | 已核对身份和相关性，用于构建领域地图与覆盖面 | 不能支撑高风险技术事实 |
| 深度核验（deep-verified） | 已打开并纳入来源、claim/evidence 与语义检查的材料 | 可以，在其版本、任务和限制范围内 |

核心结论、关键数字、版本状态、方案比较、安全和采用事实需要可靠的直接证据；一般性的架构解释则使用保守措辞、合理来源和可检查的逻辑，不把每一句拆成审计编号。GitHub 分析默认以固定版本的代码、目录、依赖和文档为准；除非实际运行会改变关键判断，不把“没有执行仓库”误写为性能或可用性的证据。

读者页使用自然语言和简洁来源链接。完整的 `sources.jsonl`、`claims.jsonl`、`evidence.jsonl`、筛选、饱和、语义检查与原始检索记录保留在 [v09 bundle](../../agent-memory-v09/bundle/) 及其 `mapping/`、`work/` 目录。读者层与审计层相互链接，但彼此不替代。

## 范围与时间边界

本套件关注外部、跨会话或跨任务的 Agent Memory：它承担状态的写入管理、检索使用或持续演化。长上下文、普通 RAG、参数记忆、持续学习、checkpoint 和一般工作流状态会在必要时作为边界或替代方案出现，但不是默认的主体分支；只有当它们实际承担上述 Memory 职责时才进入分析。

时间上，读者页优先解释当前主流、最近 12 个月的实质进展及最近 90 天的弱信号。较早工作只在理解今天的机制时简短出现。新并不自动表示成熟；单一仓库快照、star 数、README 自述或预印本都不能单独证明质量、性能、采用或趋势。

## 如何阅读判断

文中的成熟度、代价、失败模式、共识、争议和“证据偏强/偏弱”是描述性判断：它们说明某个机制在什么条件下成立、已知什么和还不知道什么。它们不是技术选型建议。

尤其是“通用架构模型”只解剖现有系统常见的模块和数据流：写入、管理、存储、检索、上下文构造、使用和反馈，以及安全、权限、成本与评测如何横切其中。它可以显示多个变体会替换或省略哪些模块，但不表示行业唯一标准，也不提供默认组合、统一冠军、上线方案或最小验证清单。

## 已知限制与人工介入

v09 的主要限制包括未执行第三方仓库、公共索引与 GitHub 偏倚、部分新工作缺少独立复现、跨后端可比评测不足，以及动态状态只能确认到冻结日期。读者正文会把影响结论的缺口译成“目前不知道什么、为什么不知道、影响哪种判断”，而不把审计术语推给读者。

完整首版不依赖人工审批。只有证据冲突、代表性难以客观确定、近期信号可能改变领域判断，或是否继续深挖取决于读者关注场景时，才把少量事项列入 [人工评审](human-review.md)。人工的作用是改判、调整重点或触发增量深挖，不是补写正文。
