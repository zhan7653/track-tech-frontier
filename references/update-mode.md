# Update Mode

Read the prior reader suite, research plan, mapped corpus, repository observations, trends, deep evidence, syntheses, gaps, and audit material before searching. Preserve the prior bundle unchanged.

1. Preserve the reader contract unless the user changes it; allow mechanism branches, scenario views, and derived questions to evolve.
2. Search from the prior as-of through the new as-of with overlap for delayed indexing; rerun rolling 90-day and 12-month discovery and revisit older work only when it changes interpretation of a current route.
3. Recheck mutable repositories, releases, standards, products, benchmarks, withdrawals, corrections, and migration/deprecation status.
4. Append dated repository observations rather than overwriting them. Recalculate momentum only when observation history supports it.
5. Classify entity changes as `new`, `updated`, `corrected`, `withdrawn`, `renamed`, `superseded`, `reclassified`, or `newly-discovered-old`.
6. Re-run map and merge/split review. A new item may create or change a mechanism branch, alter a scenario view, or move a boundary.
7. Reopen affected descriptive judgments, consensus assessments, trend signals, and reader synthesis. Preserve prior minority and contradictory evidence.
8. Deeply verify material new entities and old entities whose current state changed. Do not force the full old discovered corpus through deep verification.
9. Produce a complete current reader suite plus a dated delta that separates corpus, map, trend, evidence, and judgment changes. Do not frame the delta as a new selection recommendation.
10. Preserve compatibility links to the prior bundle and make new changes visible in the relevant overview, branch, scenario, and project material rather than only in an appended bibliography.

An update is not merely a source append. If current practice, a mechanism boundary, engineering state, consensus, or uncertainty changes, rewrite the affected reader material and any linked audit records.
