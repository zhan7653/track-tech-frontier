# 怎样阅读这份 HTML 展示研究

问题不是“把 Markdown 涂上一层 CSS”，而是怎样让第一次进入一个技术领域的读者形成心智地图、重建机制、比较分支，并随时回到证据。

## 三条阅读路径

- **8 分钟形成判断：** [结论总览](overview.md) → [展示架构](architecture.md)。
- **20 分钟理解设计空间：** 再读[方案全景](solution-landscape.md)和[评估框架](evaluation.md)。
- **实现前核查：** 进入[机制分支](mechanisms/README.md)和[项目深挖](projects/README.md)，最后看[方法与范围](method-and-scope.md)。

## 读完应能回答

1. 为什么研究套件同时需要“跨文件定位”和“单页专注阅读”。
2. 哪些交互真的帮助理解，哪些只是把页面做得更像应用。
3. 怎样在不破坏 Markdown 权威源的前提下生成可离线、可打印、可测试的 HTML。
4. Mermaid、比较表、证据链接和不确定性怎样变成可读的解释组件。
