# Agent Memory 方案全景：不同路线到底在改变什么

**证据截止：2026-08-10**

Agent Memory 的方案很容易被项目名和新术语淹没。更清楚的读法是：先看它们修改了生命周期中的哪一段，再看它们保存什么对象、引入什么额外状态，以及把复杂度放在写入、维护还是读取阶段。

本页是跨分支索引。它不会取代六份机制深度报告，也不把不同任务的结果拼成排行榜。

## 1. 全领域的方案坐标

| 生命周期位置 | 主要方案族 | 它试图解决什么 | 引入的主要代价 | 深入阅读 |
|---|---|---|---|---|
| 记忆对象 | 原始事件、原子事实、画像、关系/时态状态、程序/技能、项目/世界/共享状态 | 避免把语义完全不同的状态都当成文本块 | schema、作用域和版本模型变复杂 | [对象与作用域](mechanisms/01-memory-objects-and-scope.md) |
| 写入形成 | 全量保留、规则接纳、模型抽取、反思/巩固、策略控制 | 控制长期状态的质量、体积与可用性 | 模型调用、误写、信息损失和污染入口 | [写入与形成](mechanisms/02-write-and-formation.md) |
| 表示与访问 | 文本/向量、混合索引、图、时间/版本化、多后端/文件分层 | 让不同类型的问题能找到正确状态 | 建图、同步、重建、事务和迁移 | [表示、存储与索引](mechanisms/03-representation-storage-indexing.md) |
| 管理演化 | 追加版本、合并替代、衰减/遗忘、清除、学习型操作选择 | 处理状态变化、噪声、预算与删除 | 策略错误、不可逆损失和恢复复杂性 | [生命周期与演化](mechanisms/04-lifecycle-and-evolution.md) |
| 读取构造 | 语义/关键词/字段过滤、图导航、时间感知、主动检索、上下文压缩 | 在主体、时间、权限和预算下给出最小充分证据 | 多阶段延迟、调参、不可比评测和解释成本 | [检索与上下文](mechanisms/05-retrieval-and-context.md) |
| 使用反馈 | 回答辅助、偏好调节、经验反思、程序/技能、行动反馈与共享修改 | 让过去真正改变未来行为 | 过期条件、错误自强化、行动越权与污染传播 | [使用、反馈与技能](mechanisms/06-use-feedback-and-skills.md) |

## 2. “记忆对象”路线：差别不只是格式

### 原始经历与事件日志

这一路线保留对话、工具调用、环境事件或文件变化，尽量推迟不可逆解释。它保留细节和可追溯性，适合重新抽取与复盘；代价是规模增长、检索负担和敏感信息保留。

### 原子事实与语义状态

系统把经历转成较小的事实、属性或关系，并处理重复和更新。它比长摘要更容易精确检索，却要求系统区分“观察到的内容”和“模型推断”，并保存来源、有效时间和冲突。

### 用户画像与身份状态

这一路线将偏好、关系和长期属性作为独立对象。它能支持跨会话连续性，但扩大隐私、身份漂移、错误画像和跨用途泄露问题。画像越丰富，并不自动意味着净效用越高。

### 程序、经验与技能

系统保存反思、轨迹、指令、脚本或可执行技能，让 Agent 复用过去的行为资产。复用单位越接近执行，适用条件、工具版本、权限和验证责任越重要。

### 项目、世界与共享状态

项目记忆绑定仓库、分支、提交和任务；世界状态绑定空间、时间和观察；共享状态绑定主体、权限和合并关系。它们都不能安全地退化为无作用域的全局文本池。

## 3. “写入形成”路线：把复杂度放在哪里

| 写入路线 | 形成方式 | 主要优势 | 主要失败方式 |
|---|---|---|---|
| 全量/近全量记录 | 保存原始历史，读取时再判断 | 信息损失少、可追溯 | 规模和敏感数据增长，读取成本高 |
| 规则与阈值接纳 | 用类型、重复度、重要性或预算规则筛选 | 行为可解释、成本可控 | 固定规则难覆盖新任务，阈值脆弱 |
| 模型抽取与摘要 | LLM 生成事实、画像或摘要 | 能处理开放文本 | 幻觉、过度概括、来源丢失 |
| 反思与巩固 | 从一组事件形成更稳定的结论或经验 | 减少噪声、提高复用 | 提前丢失未来才显重要的细节 |
| 学习型写入策略 | 根据状态和任务选择写入/更新/忽略 | 可适应预算和任务变化 | 策略漂移、难解释、错误被长期放大 |
| 人或工作流确认 | 高风险候选进入确认/审批 | 可控制重大错误 | 延迟和人工负担，不适合所有写入 |

这些方案不是互斥的。公开系统常见的组合是保留一部分原始证据，同时生成可重建的结构化投影；低风险内容自动接纳，高风险或冲突内容进入更严格路径。

## 4. “表示与索引”路线：权威状态与访问面

### 文本与向量

文本记录配合向量召回仍是最常见的工程起点。它对表达差异具有弹性，接口和基础设施成熟；但对于精确身份、时间、版本、关系和冲突，只靠相似度往往不足。

### 混合检索

混合路线组合向量、关键词、字段和元数据过滤。它反映了一个越来越明确的事实：精确事实与语义近似是不同访问需求。其代价是多个分数、索引和预算如何组合并无统一答案。

### 图与关系记忆

图路线将实体、事件和关系显式连接，支持多跳和结构导航。它在关系密集任务中具有表达优势，但“图记忆”并不是单一方法：图的构建、更新、遍历和与原始证据的连接方式差异很大，成本也常被低估。

### 时间与版本化状态

这一路线区分观察时间、事实有效时间和系统记录时间，保留旧版本、替代与冲突。它更适合回答“当时是什么”“现在为什么改变”，但需要更明确的 schema、事务和生命周期操作。

### 分层文件与多后端系统

Coding Agent 和 Memory 服务中常见文件/对象层级、关系数据库、向量索引与图后端并存。它们提高可读性和适配能力，也带来能力差异、派生索引落后、迁移和恢复边界。

## 5. “管理演化”路线：保留、压缩、替代还是删除

### 追加与版本化

每次变更形成新版本，保留前后关系。这种方式利于追溯和恢复，存储与查询则更复杂。

### 合并与巩固

多个事件被汇总为事实、画像或经验。它减少碎片和读取成本，但总结的损失常常直到未来问题出现才暴露。

### 衰减与遗忘

系统按时间、使用或预算降低可见性，或主动清除内容。衰减、停止召回、逻辑撤销和物理删除有不同语义；隐私删除还涉及摘要、索引、缓存、备份和行为依赖。

### 学习型控制

控制器根据任务选择重检索、合并、遗忘或无操作，是近期的重要信号。它把固定规则升级为在线策略，也把安全边界推进到“谁能改变长期状态、错误操作能否回滚”。

## 6. “读取与上下文”路线：召回只是中间步骤

| 读取路线 | 主要机制 | 适合处理的问题 | 主要不确定性 |
|---|---|---|---|
| 语义 top-k | embedding 相似度 | 表述变化的相关经历 | 时间、冲突和权限依赖额外过滤 |
| 关键词/字段过滤 | BM25、精确字段、metadata | 标识符、专名、明确条件 | 语义改写和关系问题较弱 |
| 混合召回与重排 | 多路候选融合 | 通用事实与对话回忆 | 分数和预算组合依赖任务 |
| 图/关系导航 | 实体、边、PPR、多跳 | 关联与多跳问题 | 建图质量、维护成本和协议不可比 |
| 时间/版本感知 | as-of、有效期、替代链 | 更新、历史和冲突 | 时间语义需要写入阶段支持 |
| 主动多轮检索 | 根据已见证据继续规划搜索 | 复杂、多步、证据稀疏任务 | 额外模型调用、延迟和错误扩散 |
| 上下文压缩/编译 | 摘要、分层加载、token packing | 长任务与固定上下文预算 | 关键细节损失和不可见偏差 |

## 7. “使用与反馈”路线：从记得转向会用

有些系统只把记忆作为回答上下文；有些让记忆影响用户画像、计划或工具参数；另一些把成功与失败轨迹提炼为可复用程序。评测对象由此发生变化：事实问答正确并不能证明工具行动正确，检索到技能也不能证明它仍适用于当前版本和权限。

反馈又形成下一轮写入。它可以修正状态，也可能让系统将自己的错误经验不断强化。近期对经验污染、技能晋升和 memory-to-action 的关注，正说明领域开始把终点从“recall”移动到“行为及其后果”。

## 8. 工程实现的四种外形

| 外形 | 公开实现通常暴露什么 | 它能说明什么 | 它不能单独说明什么 |
|---|---|---|---|
| SDK/库 | `add/search/update/delete`、provider adapters | 接口和后端组合 | 长期一致性、生产采用、安全保证 |
| 独立 Memory 服务 | API、存储、worker、管理操作 | 多 Agent/应用共享的控制面 | 跨租户与故障恢复是否充分 |
| Agent runtime 内建状态 | session、blocks、checkpoint、context management | 与推理循环的真实连接 | 是否具有通用外部 Memory 语义 |
| 文件/协议/可移植层 | schema、目录、adapter、test vectors | 交换和人工审阅的工程尝试 | 已形成标准或跨实现无损互操作 |

## 9. 当前主流和新方向怎样区分

当前主流工程仍围绕外部持久层、向量或混合检索、用户/会话/项目作用域，以及 SDK/服务接入。结构化状态、图与时态表示、自动生命周期管理、程序性经验、共享记忆、可移植协议和全链安全正在快速扩展，但成熟度并不一致。

最近 12 个月更明显的变化不是某个存储后端胜出，而是：

- 写入、更新、遗忘开始被建模为显式操作或策略；
- 评测从长对话回忆扩展到更新、工具行动、可靠性和安全；
- Coding Agent 的项目/环境状态形成独立工程生态；
- 共享、可移植与项目协议快速增多，但独立互操作证据仍薄弱；
- 经验和技能的自动晋升带来新的错误传播与安全问题。

最近 90 天出现大量新论文与仓库，其中许多强化这些既有方向，而不是形成新的一级架构。详见[近期变化](trends.md)。
