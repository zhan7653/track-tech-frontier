# Research brief

Topic: HTML presentation patterns for technical frontier research reports

As of: 2026-08-24

## Reader contract

- **Reader:** technically literate readers who are new to the report's specialty and need to understand mechanisms, not merely browse source lists.
- **Default entry:** one generated static HTML site opened from a research bundle, with the overview as the first reading path.
- **Scope:** open-source repositories, maintained documentation tools, and Codex skills whose concrete presentation mechanics can improve this repository's Markdown research suites.
- **Non-goals:** recommending a universal documentation stack, replacing Markdown as the source of truth, building a hosted service, or adding an application framework that the static output does not need.
- **Non-negotiable questions:** how readers orient across a large report suite; how HTML can reconstruct mechanisms and data flows; how comparisons, evidence, uncertainty, and freshness remain legible; how the output works offline and degrades safely; and how the generator stays testable and dependency-light.

## Pilot mechanism map

1. Entry, hierarchy, and progressive disclosure.
2. Navigation, search, cross-document continuity, and deep linking.
3. Mechanism explanation through diagrams, annotated flows, tables, and callouts.
4. Evidence, citations, freshness, confidence, and provenance surfaces.
5. Static generation, Markdown compatibility, portability, and extension boundaries.
6. Typography, responsive behavior, accessibility, printing, and failure states.

The map is provisional until the multi-lane pilot is screened. Recent releases are treated as mutable signals; older projects remain eligible when they explain current practice.
