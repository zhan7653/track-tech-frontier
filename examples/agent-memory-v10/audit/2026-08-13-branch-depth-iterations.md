# 2026-08-13：机制分支深度迭代记录

## 起点

commit `6464350` 的六篇机制报告已经比 v10 初稿更完整，但仍属于中等深度：每篇约五至六个方案段落，缺少独立的算法展开、完整系统 walkthrough 和输入吸收对照。它们被视为本轮中间稿，不是最终版本。

## Round A — 机制展开

状态：完成。

目标：把六个单页分支改成六个专题包。每包保留一篇可顺读入口，并新增三篇深潜：方案内部、代表系统、前沿与反证。重点不是增加项目数量，而是解释状态结构、算法步骤、数据流、控制决策和失败位置。

结果：新增 18 篇深潜。六个专题都已形成“内部机制 / 固定版本工程 / 反证、成本与前沿”三层；生命周期初稿偏薄，随后补入固定 commit 的 promotion/outbox、bi-temporal/multi-store、FTS rebuild、encrypted journal，以及派生修复、故障注入和共同实验。

## Round B — 输入回填

状态：完成。

目标：依据[输入吸收矩阵](2026-08-13-branch-absorption-matrix.md)，逐项检查 v09 的主干机制、固定版本工程剖面、benchmark 和反证是否真正进入分析；记录有意留在长尾地图的材料及原因。

结果：见[输入吸收复核](2026-08-13-branch-absorption-review.md)。复核没有以名称出现为通过条件；主干材料分别进入状态结构/算法、固定版本数据流、实验条件、反证或研究议程。长尾 metadata、同形项目和普通 RAG/框架 feature 仍留在 v09 广度地图，避免正文重新退化为清单。

## Round C — 读者编辑

状态：完成。

目标：重排入口与深潜之间的关系，消除重复、论文列表化、审计语言和跳跃式叙述。以独立读者能否复述内部机制、系统差异与近期研究议程作为验收，而不是使用字数或绿色验证器替代。

结果：六个入口均新增三路深潜导航；总索引改为 6×3 阅读矩阵；主版本说明精确区分 2026-08-10 主快照、2026-08-12 窄幅机制补查和 2026-08-13 深潜重编；清除了过期“后续再补”措辞。读者复述结果见[独立于账本的抽查记录](2026-08-13-reader-reconstruction-review.md)。

## Round D — 一致性与回归

状态：机械检查完成；独立只读复核按冻结提交身份记录，不回写读者正文。

目标：验证链接、UTF-8、arXiv 来源注册、读者结构、测试和 Git 差异；把分支 package 与输入吸收规则同步回通用 Skill；最后对冻结提交做独立只读复核。

结果：读者套件结构检查覆盖 63 个 Markdown 文件；仓库测试在本轮扩充到 115 项并通过，安装中的个人 Skill 回归测试 104 项通过，`git diff --check` 通过。18 篇深潜均已由专题清单登记并从对应入口直达。`skill-creator` 的 `quick_validate.py` 因当前两个 Python 运行时都缺少 PyYAML 而未执行；本轮没有改动 YAML/frontmatter，改以文件哈希一致性、既有 Skill 测试和结构检查覆盖相关风险。

首轮独立只读复核确认六个专题都已具有可重建的数据流、实质方案差异、工程边界和机制级研究议程，同时指出三类交付偏差：四处安全/控制文字仍写成架构或行动建议；旧内部分类映射仍位于 `reader/`；专题清单校验器未拒绝非 object 根和越界路径。后续候选将这些内容分别改为描述性设计模式、下沉到 `audit/`，并增加 manifest 根类型与 suite 路径约束及回归测试。复核以冻结 commit 与 clean worktree 为身份，不用绿色验证器代替内容判断。
